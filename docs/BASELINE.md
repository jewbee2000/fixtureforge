# M0 baseline and usefulness gate

Executed locally on 2026-10-04 with Python 3.12.2, Windows 11 x64, CadQuery 2.8.0,
build123d 0.12.0, CADCLAW 0.10.0 and OCCT bindings 7.9.3.1.1. The dependency
resolver selected build123d 0.12.0 to share the compatible kernel version.
`pip check` passed. Full pins: requirements-lock.txt; source and STEP hashes:
evidence/baseline.json. Primary sources:
[CADCLAW](https://github.com/sunnyday-technologies/CADCLAW/tree/v0.10.0),
[interference](https://github.com/sunnyday-technologies/CADCLAW/blob/v0.10.0/cadclaw/interference.py),
[disassembly](https://github.com/sunnyday-technologies/CADCLAW/blob/v0.10.0/cadclaw/disassembly.py),
[CadQuery](https://cadquery.readthedocs.io/en/latest/),
[build123d](https://build123d.readthedocs.io/en/latest/).

Run `python scripts/baseline.py`. This script imports no FixtureForge code.
Both synthetic cases place a 1×1×4 mm obstacle at Z=5. A radius-1, height-2
cylinder or a 2×2×2 box moves from Z=0 to Z=10. Both endpoint intersections
are zero. The full axial sweep intersects 4 mm³. CadQuery and build123d agree.
CADCLAW finds zero endpoint collisions and one collision when supplied the
sweep. A 10 mm cube STEP round trip measures 1000 mm³. Generated STEP files
are retained under artifacts/baseline and regenerated by the script.

CADCLAW already handles general static interference, inventory, dimensions and
reports. Its reviewed disassembly routine exports displaced poses rather than
checking a full path. Its interference routine is useful with authored sweep
solids, but its prefilter and exception handling do not supply this project's
strict incomplete-result contract. See the pinned source hashes for scope.

**Decision: proceed with a small integration.** CadQuery constructs and checks
bounded sweeps; FixtureForge adds explicit path/occupancy/contact data, named
obstruction reports, and fail-closed resource handling. Exported sweep STEP
files remain usable by CADCLAW through scripts/cadclaw_check.py. No generic CAD
validator, native CAD controller, or motion planner is warranted.

This proves a reproducible workflow gap in the reviewed versions, not uniqueness
or market demand. Direct CadQuery is already sufficient for a short custom
script. The added value must therefore be reusable input contracts and reports
that work in the separate consumer walkthrough. No practitioner feedback exists.

Timing in baseline.json covers geometry after imports, not environment setup or
cold interpreter startup; M4 records wall time and peak RSS separately.
